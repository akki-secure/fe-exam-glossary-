システム構成要素編(穴埋め)

89 語 fe-siken.com 用語集(シラバスVer9.2)をもとに作成

システムの構成

・(　　　　　　　　) →データをある程度まとめて、一括して処理する方式。

・(　　　　　　　　) →要求を受けたら、決められた時間内に、必ず処理して応答する方式。航空機の制御、銀行のATM。

・(　　　　　　　　) →複数の処理を、複数のプロセッサで、同時に行うこと。

・(　　　　　　　　) →依頼する側(クライアント)と、処理する側(サーバ)で、役割を分担して行う処理。

・(　　　　　　　　) →ひとまとまりの処理を、確定または取消しの単位として、扱う処理方式。

・(　　　　　　　　) →利用者が、コンピュータとやり取りしながら、進める処理方式。

・(　　　　　　　　) →2系統のシステムで同じ処理を同時に行い、結果を照合する構成。

・(　　　　　　　　) →同じシステムを2系統用意し、1つを予備にしておく構成。

・(　　　　　　　　) →複数のコンピュータを連携させて、1台のように動かす構成。

・(　　　　　　　　) →複数のプロセッサを備えて、処理を分担するシステム。

・(　　　　　　　　) →複数のシステムで、負荷を分け合って処理する構成。

・(　　　　　　　　) →災害などに備えて、別の場所に用意する、予備のシステムの拠点。

・(　　　　　　　　) →本番と同じ環境を、常時稼働させておく、バックアップサイト。すぐ切り替えられる。

・(　　　　　　　　) →機器は用意しておくが、データの同期などは、切替時に行うバックアップサイト。

・(　　　　　　　　) →場所や設備だけを、用意しておくバックアップサイト。復旧に時間がかかる。

・(　　　　　　　　) →通常時に、処理を行うほうのシステム。

・(　　　　　　　　) →主系に障害が起きたとき、代わりに動く、予備のシステム。

・(　　　　　　　　) →複数のプロセッサが、メモリを共有して、密接に連携している構成。

・(　　　　　　　　) →複数のシステムが、それぞれ独立し、通信で連携している構成。

・(　　　　　　　　) →特定のサーバを置かず、対等な端末同士が、直接やり取りする方式。

・(　　　　　　　　) →ネットワークでつないだ、多数のコンピュータを、1つの大きな計算機として使う技術。

・(　　　　　　　　) →1台のコンピュータの上に、複数の仮想的なコンピュータを作る技術。

・(　　　　　　　　) →1台の物理的なコンピュータ上で動作する、仮想的なコンピュータ。

・(　　　　　　　　) →デスクトップ環境を、サーバ上に集約して、端末から利用する仕組み。

・(　　　　　　　　) →インターネット経由で、必要な分だけコンピュータ資源をサービスとして利用する形態。

・(　　　　　　　　) →サーバやネットワークの構成を、コードで記述して、自動的に構築する手法。

・(　　　　　　　　) →ソフトウェアの機能をインターネット経由で提供するクラウドサービス。Web上のメールサービス。

・(　　　　　　　　) →アプリケーションを動かすための環境(基盤)をインターネット経由で提供するサービス。

・(　　　　　　　　) →サーバやネットワークなどのインフラをインターネット経由で提供するサービス。

・(　　　　　　　　) →利用者がサーバの管理を意識せずに、プログラムを実行できる、クラウドの仕組み。

・(　　　　　　　　) →関数(プログラム)単位で、クラウド上で実行できるサービス。

・(　　　　　　　　) →データの発生源の近くで処理を行い、通信の遅延や負荷を減らす方式。

・(　　　　　　　　) →システムやデータを、別の環境へ移行すること。

・(　　　　　　　　) →OSI参照モデルの第6層。データの表現形式の変換を扱う。

・(　　　　　　　　) →3層構造のシステムで、業務処理を担う層。

・(　　　　　　　　) →3層構造のシステムで、データベースへのアクセスを担う層。

・(　　　　　　　　) →サービスを依頼する側の、コンピュータやソフトウェア。

・(　　　　　　　　) →サービスを提供する側の、コンピュータやソフトウェア。

・(　　　　　　　　) →端末に最低限の機能だけを持たせ、処理やデータをサーバ側で管理する方式。

・(　　　　　　　　) →ネットワーク上の、別のコンピュータにあるプログラムを、手元にあるように呼び出す仕組み。

・(　　　　　　　　) →Webブラウザを使って利用するシステム。

・(　　　　　　　　) →Webページを閲覧するための、ソフトウェア。

・(　　　　　　　　) →Webページのデータを、Webブラウザの要求に応じて送るサーバ。

・(　　　　　　　　) →データを複数のディスクに分散して書き込む方式。高速だが冗長性はない。

・(　　　　　　　　) →同じデータを2つのディスクに書き込む方式。1台が壊れても平気。

・(　　　　　　　　) →ミラーリングとストライピングを組み合わせた方式。

・(　　　　　　　　) →データをビット単位で分散し、ハミング符号で誤り訂正する方式。

・(　　　　　　　　) →データをビット/バイト単位で分散し、専用のディスクにパリティを記録する方式。

・(　　　　　　　　) →データをブロック単位で分散し、専用のディスクにパリティを記録する方式。

・(　　　　　　　　) →パリティ(誤り訂正情報)を分散して記録する方式。1台が壊れても復旧できる。

・(　　　　　　　　) →パリティを2種類記録する方式。2台が同時に壊れても復旧できる。

・(　　　　　　　　) →データを分割して、複数のディスクに並行して書き込む方式。

・(　　　　　　　　) →同じデータを、複数のディスクに、同時に書き込む方式。

・(　　　　　　　　) →誤りの検出や、データの復元のために付ける、検査用の情報。

・(　　　　　　　　) →ネットワークにつないで、ファイルを共有するための、専用の記憶装置。

・(　　　　　　　　) →ストレージを、専用の高速ネットワークで、つないだシステム。

・(　　　　　　　　) →システムに、障害を引き起こす原因となる、欠陥や故障。

・(　　　　　　　　) →故障が起きても、多重化などで、その影響が表に出ないようにする方法。

・(　　　　　　　　) →一部が故障しても、システム全体は動き続けられるように、設計されたシステム。

・(　　　　　　　　) →故障の発生自体を、避けるという考え方。高品質な部品の採用など。

・(　　　　　　　　) →故障が起きたとき、安全な方向へ動作させる設計の考え方。信号機が故障したら全方向を赤にする。

・(　　　　　　　　) →故障が起きたとき、機能を絞ってでも運転を続ける設計の考え方。

・(　　　　　　　　) →利用者が誤った操作をしても、危険な状態にならないようにする設計の考え方。

・(　　　　　　　　) →片方を稼働させ、もう一方を待機させておく構成。

・(　　　　　　　　) →複数のシステムを、すべて稼働させておく構成。

システムの評価指標

・(　　　　　　　　) →処理を依頼してから、結果の返答が始まるまでの時間。

・(　　　　　　　　) →処理を依頼してから、すべての結果が返ってくるまでの時間。

・(　　　　　　　　) →単位時間あたりに処理できる仕事の量。

・(　　　　　　　　) →標準的なプログラムを実行して、コンピュータの性能を測る方法。

・(　　　　　　　　) →データベースの、トランザクション処理性能を測る、ベンチマーク。

・(　　　　　　　　) →整数演算を中心とした、CPUの性能を測るベンチマーク。

・(　　　　　　　　) →浮動小数点演算を中心とした、CPUの性能を測るベンチマーク。

・(　　　　　　　　) →システムの稼働状況や、性能を、継続的に監視すること。

・(　　　　　　　　) →将来の利用量を予測して、必要な処理能力を計画すること。

・(　　　　　　　　) →必要な性能から、システムの規模や構成を、見積もること。

・(　　　　　　　　) →サーバの台数を増やして、システムの処理能力を高めること。

・(　　　　　　　　) →1台のサーバの性能を、高めて処理能力を上げること。

・(　　　　　　　　) →将来の需要を見越して、システムの容量や処理能力を、計画的に管理すること。

・(　　　　　　　　) →必要な資源を、用意して、使える状態にすること。

・(　　　　　　　　) →RASに、保全性・完全性を加えたシステムの評価の観点。

・(　　　　　　　　) →故障から次の故障までの平均時間。長いほど信頼性が高い。

・(　　　　　　　　) →故障してから修理が終わるまでの平均時間。短いほど保守性が高い。

・(　　　　　　　　) →システムが正常に動いている時間の割合。MTBF÷(MTBF+MTTR)で求める。

・(　　　　　　　　) →機器の故障率が、初期・偶発・摩耗の時期で変化する様子を表した曲線。

・(　　　　　　　　) →システムの導入時にかかる初期費用。

・(　　　　　　　　) →システムの運用にかかり続ける費用。

・(　　　　　　　　) →システムの導入から運用、廃棄までにかかる総費用。

・(　　　　　　　　) →特定のシステムなどに対して、直接かかった費用。

・(　　　　　　　　) →特定のシステムなどに、直接ひもづけられない、共通してかかる費用。
