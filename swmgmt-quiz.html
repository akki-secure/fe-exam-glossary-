ソフトウェア開発管理技術編(穴埋め)

40 語 fe-siken.com 用語集(シラバスVer9.2)をもとに作成

開発環境の管理

・(　　　　　　　　) →ソフトウェアの構成要素(ソースやドキュメントなど)を、一貫して管理すること。

・(　　　　　　　　) →ソフトウェアへの変更を、決められた手続きで管理すること。

・(　　　　　　　　) →ファイルの変更履歴を記録し、過去の状態を取り出せるようにすること。

・(　　　　　　　　) →ソースコードなどの資産と、その変更履歴を保管する場所。

・(　　　　　　　　) →分散型のバージョン管理システム。

・(　　　　　　　　) →開発の流れを分けて、並行して作業できるようにする仕組み。

・(　　　　　　　　) →分かれたブランチの変更を、1つにまとめること。

・(　　　　　　　　) →ソースが変更されるたびに、自動でビルドやテストを行う開発手法。継続的インテグレーションともいう。

・(　　　　　　　　) →テストを通ったソフトウェアを、自動的にリリースまで行う手法。継続的デリバリともいう。

・(　　　　　　　　) →ソースコードから、実行できる形のプログラムを作ること。

・(　　　　　　　　) →エディタやデバッガなどの開発道具を、まとめて使えるようにしたソフトウェア。IDEともいう。

・(　　　　　　　　) →ソフトウェア開発の作業を、コンピュータで支援するツールの総称。

開発手法・レビュー

・(　　　　　　　　) →開発の成果物を、関係者で確認し、誤りを早期に発見する活動。

・(　　　　　　　　) →作成者が、関係者に成果物を説明しながら、誤りを指摘してもらうレビュー。

・(　　　　　　　　) →専門の検査者が、決まった手順で厳格に行うレビュー。

・(　　　　　　　　) →2人1組で、1台のコンピュータを使ってプログラムを書く手法。

・(　　　　　　　　) →先にテストを書き、それを通るようにプログラムを作る開発手法。TDDともいう。

・(　　　　　　　　) →開発と運用に加えて、セキュリティも最初から組み込む考え方。

・(　　　　　　　　) →すでにある部品や設計を、別の開発に使い回すこと。

・(　　　　　　　　) →完成した状態で、販売されているソフトウェア。

・(　　　　　　　　) →再利用しやすい単位にまとめた、ソフトウェアの部品。

品質管理

・(　　　　　　　　) →ソフトウェアが、利用者の要求を満たしている度合い。

・(　　　　　　　　) →ソフトウェアが、必要な機能を備えているかどうかという品質。

・(　　　　　　　　) →ソフトウェアが、安定して動き続けるかという品質。

・(　　　　　　　　) →利用者にとって、使いやすいかという品質。

・(　　　　　　　　) →資源や時間を、無駄なく使えるかという品質。

・(　　　　　　　　) →修正や改良が、しやすいかという品質。

・(　　　　　　　　) →別の環境へ移しても、動かしやすいかという品質。

・(　　　　　　　　) →ソフトウェアの品質を、評価するための国際規格。

・(　　　　　　　　) →製品が、要求された品質を満たすことを、保証するための活動。

・(　　　　　　　　) →品質を、目標どおりに保つための活動。

・(　　　　　　　　) →発見したバグの累積数を、時間の経過に沿って表したグラフ。信頼度成長曲線の目安にする。

・(　　　　　　　　) →プログラムの規模あたりの、バグの数。1,000行あたり5件など。

・(　　　　　　　　) →ソフトウェアの規模や品質を、数値で測るための尺度。

・(　　　　　　　　) →プログラムの、命令の行数。ソフトウェアの規模を表す指標。

・(　　　　　　　　) →機能の数と複雑さから、ソフトウェアの規模を見積もる方法。

開発の知的財産

・(　　　　　　　　) →プログラムなどを作った人に、自動的に生じる権利。

・(　　　　　　　　) →ソフトウェアの、利用を許諾する契約や条件。

・(　　　　　　　　) →無料で使えるソフトウェア。著作権は放棄されていない。

・(　　　　　　　　) →試用期間の後、気に入れば代金を支払って使うソフトウェア。
