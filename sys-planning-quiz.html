システム化計画

・(　　　　　　　　) →システムを、効率的で、無駄がないように、整える手法。

・(　　　　　　　　) →システム化の、方向性を、関係者の間で、共有すること。

・(　　　　　　　　) →システムの、全体の設計や、利用の体験を、設計すること。

・(　　　　　　　　) →ビジネスアナリシスの、知識を、体系的にまとめた、ガイド。

・(　　　　　　　　) →企業の、業務データを、正確に記録・管理するための、システム。

・(　　　　　　　　) →顧客との、つながりや、体験を重視する、システム。

・(　　　　　　　　) →データを、分析して、洞察を得るための、システム。

・(　　　　　　　　) →独自に作り込まず、標準の機能に、業務を合わせて、導入する考え方。

・(　　　　　　　　) →組織全体の、システム化の方向性と、計画を、まとめたもの。

・(　　　　　　　　) →個別の、システムについて、具体的に、システム化を計画したもの。

・(　　　　　　　　) →システム化の、対象とする、業務や組織の範囲。

・(　　　　　　　　) →システム開発の、全体の日程。

・(　　　　　　　　) →プロジェクトを、進めるための、体制。

・(　　　　　　　　) →システムの、開発や運用に関わる人員の、教育の計画。

・(　　　　　　　　) →システム開発への、投資に対して、得られる効果。

・(　　　　　　　　) →IT投資を、種類ごとに、分類して、全体のバランスを考える手法。

・(　　　　　　　　) →システムの、企画から、廃棄までの、一生の流れ。

・(　　　　　　　　) →システムの導入に、伴うリスクを、洗い出して、分析すること。

要件定義

・(　　　　　　　　) →利用者の、要望や、必要としているものを、調べること。

・(　　　　　　　　) →現状の、業務やシステムを、調べて、問題点を明らかにすること。

・(　　　　　　　　) →分析した、問題点を、整理して、解決すべき課題を、明確にすること。

・(　　　　　　　　) →システムに、求める機能や、性能をまとめた文書。

・(　　　　　　　　) →質問を書いた、用紙などで、多くの人の、意見を集める調査方法。

・(　　　　　　　　) →関係者に、直接質問して、意見や要望を、聞き出す調査方法。

・(　　　　　　　　) →データの流れを中心に、システムを表す図。

・(　　　　　　　　) →条件と、動作の、組合せを、表にまとめたもの。決定表。

・(　　　　　　　　) →オブジェクト指向による設計を表す、標準的な図式の表記法。

・(　　　　　　　　) →業務の、データに着目して、システムを設計する考え方。データ中心アプローチ。

・(　　　　　　　　) →プロジェクトに関わる、利害関係者。顧客、経営者、開発メンバー。

・(　　　　　　　　) →会議などで、参加者の、意見を、引き出し、まとめる、進行役の技術。

調達計画・実施

・(　　　　　　　　) →開発を、自社で行うか、外部に委託するかを、判断する基準。

・(　　　　　　　　) →ソフトウェアの、部品や、外部由来の要素の供給元まで含めて、管理すること。

・(　　　　　　　　) →ソフトウェアの、ライセンスを、把握し、適切に管理すること。

・(　　　　　　　　) →調達の前に、ベンダに、技術や製品に関する情報の提供を依頼する文書。情報提供依頼書ともいう。

・(　　　　　　　　) →ベンダに、システムの提案を依頼するための文書。提案依頼書ともいう。

・(　　　　　　　　) →ベンダに、価格や、納期などの、見積りを依頼する文書。見積依頼書。

・(　　　　　　　　) →価格だけでなく、提案の内容も、評価して、契約の相手を選ぶ方式。

・(　　　　　　　　) →条件を満たす、誰もが参加できる、入札で、最も有利な条件の者と契約する方式。

・(　　　　　　　　) →ソフトウェア開発を、委託する際の、契約の、ひな形。

・(　　　　　　　　) →情報システムの、取引についての、標準的な契約書のひな形。
