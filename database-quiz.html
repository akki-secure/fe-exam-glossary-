データベース編(穴埋め)

60 語 fe-siken.com 用語集(シラバスVer9.2)をもとに作成

データベースの基本

・(　　　　　　　　) →複数のデータを整理して蓄積し、必要なときに取り出しやすくしたもの。

・(　　　　　　　　) →データベースを管理し、検索や更新などを行うソフトウェア。データベース管理システムともいう。

・(　　　　　　　　) →データを、木構造(親と子の関係)で管理するデータベース。

・(　　　　　　　　) →データ同士を、網の目のように複雑な関係で結ぶデータベース。

・(　　　　　　　　) →データを、表(テーブル)の形で管理するデータベース。RDBともいう。

・(　　　　　　　　) →表形式にこだわらず、大量のデータを高速に扱うことを重視したデータベースの総称。

・(　　　　　　　　) →関係データベースで、データを行と列で並べた表。

・(　　　　　　　　) →テーブルの1行にあたる、データのまとまり。行ともいう。

・(　　　　　　　　) →テーブルの1列にあたる、項目。列、属性ともいう。

・(　　　　　　　　) →データベースの構造(どんな項目があるか)を定義したもの。

データベース設計

・(　　　　　　　　) →現実の物事を、データベースで扱える形に整理したもの。

・(　　　　　　　　) →物(エンティティ)と、その関連(リレーションシップ)を図で表したもの。

・(　　　　　　　　) →データベースで管理する対象。社員、商品、顧客。

・(　　　　　　　　) →エンティティ同士の関連。

・(　　　　　　　　) →テーブルの中で、1つのレコードを一意に決められる項目。重複も空(ヌル)も許されない。

・(　　　　　　　　) →他のテーブルの主キーを参照する項目。テーブル同士をつなぐ。

・(　　　　　　　　) →主キーになる資格のある項目(の組)。

・(　　　　　　　　) →複数の項目を組み合わせて、1つのキーにしたもの。

・(　　　　　　　　) →値が入っていない、「不明」や「未設定」を表す特別な値。

・(　　　　　　　　) →データの重複や矛盾が起きないように、テーブルを分割して整理すること。

・(　　　　　　　　) →1つの欄に複数の値が入っている(繰返し項目)状態をなくした形。

・(　　　　　　　　) →主キーの一部だけで決まる項目を、別のテーブルへ分けた形。

・(　　　　　　　　) →主キー以外の項目で決まる項目を、別のテーブルへ分けた形。

・(　　　　　　　　) →外部キーの値が、必ず参照先の主キーに存在するように守るルール。

・(　　　　　　　　) →検索を速くするために、データの場所を記録した索引。

・(　　　　　　　　) →1つ以上のテーブルから作る、見せ方だけを定義した仮想的な表。

データ操作

・(　　　　　　　　) →関係データベースを操作するための言語。

・(　　　　　　　　) →テーブルからデータを取り出す(検索する)SQL文。

・(　　　　　　　　) →テーブルに、新しいレコードを追加するSQL文。

・(　　　　　　　　) →テーブルの、既存のレコードの値を変更するSQL文。

・(　　　　　　　　) →テーブルから、レコードを削除するSQL文。

・(　　　　　　　　) →SELECTなどで、対象とするレコードの条件を指定する部分。

・(　　　　　　　　) →指定した項目の値ごとに、レコードをグループにまとめる部分。

・(　　　　　　　　) →結果を、指定した項目の順に並べ替える部分。

・(　　　　　　　　) →合計や平均など、複数のレコードから1つの値を求める関数。SUM、AVG、COUNT、MAX、MIN。

・(　　　　　　　　) →複数のテーブルを、共通の項目でつなげて1つの表にする操作。

・(　　　　　　　　) →テーブルから、必要な列だけを取り出す操作。

・(　　　　　　　　) →テーブルから、条件に合う行だけを取り出す操作。

・(　　　　　　　　) →SQL文の中に、別のSELECT文を入れて使うこと。サブクエリともいう。

・(　　　　　　　　) →新しいテーブルを作成するSQL文。

トランザクション管理

・(　　　　　　　　) →データベースに対する、ひとまとまりの処理の単位。銀行振込は「引出し」と「預入れ」が1組。

・(　　　　　　　　) →トランザクションの処理を確定し、変更を反映させること。

・(　　　　　　　　) →トランザクションの処理を取り消して、開始前の状態に戻すこと。

・(　　　　　　　　) →トランザクションが備えるべき、原子性・一貫性・独立性・耐久性の性質。

・(　　　　　　　　) →トランザクションの処理が、すべて実行されるか、まったく実行されないかのどちらかであること。

・(　　　　　　　　) →トランザクションの前後で、データの整合性が保たれること。

・(　　　　　　　　) →同時に実行しても、互いの処理が影響しないこと。

・(　　　　　　　　) →コミットした結果が、障害が起きても失われないこと。

・(　　　　　　　　) →同じデータを同時に更新しないよう、順番に処理させる制御。

・(　　　　　　　　) →他の処理が読むことは許すが、更新を許さないロック。

・(　　　　　　　　) →他の処理の読み書きを、すべて許さないロック。

・(　　　　　　　　) →お互いが相手のロックの解除を待ち続け、処理が進まなくなる状態。

・(　　　　　　　　) →データベースの更新履歴を記録したファイル。障害からの復旧に使う。

・(　　　　　　　　) →障害の後、バックアップにログを適用して、障害直前の状態まで復旧すること。

・(　　　　　　　　) →メモリ上のデータをディスクへ書き出し、復旧の基準点を作る仕組み。

データ分析

・(　　　　　　　　) →意思決定のために、各システムのデータを集めて時系列に整理した大規模なデータベース。

・(　　　　　　　　) →大量のデータから、有用な規則や傾向を見つけ出す技術。

・(　　　　　　　　) →従来の方法では扱いきれない、大量で多様なデータ。

・(　　　　　　　　) →文章のデータから、有用な情報を取り出す技術。

・(　　　　　　　　) →企業のデータを分析して、経営の意思決定に役立てる手法。
