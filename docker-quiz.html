Docker編(穴埋め)

19 語 利用者作成のメモをもとに独自にまとめた用語集

・(　　　　　　　　) →アプリと、その実行に必要な環境を丸ごとまとめて、どこでも同じように動かせるようにする軽量なツール。

・(　　　　　　　　) →アプリ、OS(の一部)、ソフトウェア、設定をまとめた、コンテナを起動するためのひな形。たこ焼き器の「型」のように、これをもとに同じ環境をいくつでも作れる。読み取り専用。

・(　　　　　　　　) →イメージをもとに起動した、他から隔離された実行環境。同じイメージから複数起動できる。

・(　　　　　　　　) →イメージを構成する「層」。Dockerfileの命令ごとに1層でき、積み重なって1つのイメージになる。変更のない層は再利用されるので、作り直しが速い。

・(　　　　　　　　) →イメージを保存・共有しているサーバー。Docker Hubが代表例。

・(　　　　　　　　) →レジストリ内で、同じ名前のイメージをタグ違いのバージョンごとにまとめた単位。

・(　　　　　　　　) →イメージのバージョンなどを区別する名前。「ubuntu:22.04」のコロン以降の部分。省略するとlatestになる。

・(　　　　　　　　) →イメージやコンテナにつける、名前と値のセットの付加情報(作成者名やバージョンなど)。メモ書きのようなもので、動作には影響しない。

・(　　　　　　　　) →イメージをレジストリにアップロードするコマンド。

・(　　　　　　　　) →レジストリからイメージをダウンロードするコマンド。

・(　　　　　　　　) →起動中のコンテナの状態を、新しいイメージとして自分のPC(ローカル)に保存するコマンド。

・(　　　　　　　　) →パスワードの代わりに、ログインや自動処理で本人確認に使う長い文字列。権限や有効期限を決められ、漏れたときも単独で無効にできる。

・(　　　　　　　　) →イメージの作り方(ベースイメージ、実行するコマンド、コピーするファイルなど)を順番に書いたテキストファイル。

・(　　　　　　　　) →Dockerfileで、土台にする既存のイメージ(ベースイメージ)を指定する命令。例:FROM ubuntu

・(　　　　　　　　) →Dockerfileで、イメージを作る途中に実行するコマンドを指定する命令。パッケージのインストールなどに使う。

・(　　　　　　　　) →ローカルのファイルやディレクトリを、イメージの中にコピーする命令。

・(　　　　　　　　) →コンテナを起動したときに、最初に実行されるコマンドを指定するDockerfileの命令。

・(　　　　　　　　) →複数のコンテナからなるアプリ全体を、1つの設定ファイルにまとめて、一度の操作で起動・停止できるツール。例:Webサーバー+データベース。

・(　　　　　　　　) →Node.jsのパッケージを、インストールせずに一時的に実行するコマンド。

Docker編は、利用者が学習用にまとめたメモをもとに作成した独自の用語集です。基本情報技術者試験のシラバスとは無関係です。
